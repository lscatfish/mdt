## 2. 黑屏根因与修复（重要）

### 2.1 现象
- 页面加载：`__game` 存在、getState 正常（pos/fps=60）、**无任何 console 错误**
- 但 `gl.readPixels` 5 点全 [0,0,0,0]（透明黑）
- 手动调 `renderer.render()` → **天空蓝 (135,184,247) 正常**

### 2.2 根因
`js/main.js`：`requestAnimationFrame(frame)` 只存在于 frame 函数**内部自注册**（L265），**全文件没有任何首次启动调用**——渲染循环从未启动。git 历史核实：4 个提交中该缺失从一开始就存在。

### 2.3 为什么模型验证全绿却漏了
模型的 texel 级像素测试（A/B/C/D 全过）**直接调用 render/samplePixels**，绕过了游戏启动路径——验证了"render 函数正确"，没验证"游戏真的在跑"。**这是验证盲区的又一实例**（继 B2 半格、Try mipmap、B+template 草方向之后）：验证对象 ≠ 真实运行路径。

### 2.4 修复（一行）
```js
// main.js 末尾
requestAnimationFrame(frame);
```
修复后实测：fps=239.7（真实帧率）、289 chunks、中心棕色地形/顶部草地/底部天空蓝——渲染正常。

### 2.5 用户实测与遗留小 bug（2026-08-15 记录）

修复后用户实测评级：**"还行，只有一个方块贴图稍微有点 bug，其他都好"**。
代码层疑似定位：GRASS_SIDE 草皮画在 tile 顶部行（y=0-3），而侧面 UV `v=0` 对应方块底部 → **草皮方向颠倒**（与 B+template 同类，统一颠倒故不刺眼）。模型侧面 texel 测试通过是因为断言与自身 UV 约定自洽（验证"渲染与代码一致"而非"方向与直觉一致"）。按用户要求**未修复**（相关改动已回退，仅黑屏修复保留于提交 32c37cd）。

## 6. 结论与启示

1. **提示词高度有效**：首块框架被 1:1 执行（勘察/规划/TDD/texel 验证/几何对齐/可复现脚本）——"验证指令"类提示词确实改变了思维链行为（test 352 次）
2. **验证盲区升级版**：8 个会话最系统的验证（TDD + texel）依然漏掉黑屏——**因为验证绕过了启动路径**。启示：验证清单必须含"真实用户路径冒烟测试"（加载→循环启动→画面非空），不能只测被调用的函数
3. **模型行为瑕疵**：用 MCP 测过又 npm i playwright 写可复现脚本（用户质疑合理）——验证脚本化的"过度工程"倾向
4. **黑屏一行修复**：`requestAnimationFrame(frame)` 启动调用缺失——模型写"循环函数"时漏了"启动它"，测试直接调函数所以全绿
